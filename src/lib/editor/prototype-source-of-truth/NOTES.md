# 프로토타입 — 노트 source of truth A/B

## 답하려는 질문

**마크다운을 원본으로 두었을 때(ARCHITECTURE §10.1 Option A), 커스텀 노드를 품은 마크다운이
TipTap 을 왕복하고도 그대로 남는가?**

여기서 새면 "마크다운이 source of truth" 라는 A안의 전제 자체가 깨진다. 그러면 B안
(`prosemirror-sync` 를 원본으로 두고 마크다운은 Export 시 파생)만 남는다. 이 결정에
스키마·검색 인덱스·Export·오프라인 버퍼가 전부 종속돼 있다(§10.1, §12-11).

## 실행

```sh
pnpm proto:md              # 케이스를 하나씩 넘겨보는 TUI
pnpm proto:md --summary    # 전체 판정만 한 번 출력
pnpm proto:md --dump       # 어긋난 케이스의 입출력 원문 (원인 추적용)
```

> **결정 완료 (2026-08-14): A안 채택 — ADR-0003.**
> 이 프로토타입은 제 할 일을 끝냈다. 아래는 그 근거 기록이다.
> 에디터를 실제로 만들 때까지만 남겨둔다 — 확장 정의를 옮겨 붙이면서 회귀를 재보는 데 쓴다.
> 그 작업이 끝나면 "치울 때 지울 것" 대로 지운다.

## 판정 (VERDICT) — A안 성립

2026-08-14 실행. **내용 손실 0건.** 16개 케이스 중 14개는 바이트까지 동일하게 돌아왔고,
2개는 파일이 재포맷되지만 내용은 온전하다.

판정 축을 셋으로 나눈 것이 이 프로토타입의 핵심이다. 바이트 비교만 했다면 "16개 중 9개 실패"
같은 오해를 부르는 숫자가 나왔을 것이다.

| 판정 | 뜻 | 건수 |
|---|---|---|
| 보존 | 입력과 출력이 바이트까지 동일 | 14 |
| 서식변형 | 출력을 다시 파싱하면 같은 문서 — 내용은 온전, 파일만 재포맷 | 2 |
| 손실 | 다시 파싱하면 문서가 달라짐 — 내용이 사라짐 | **0** |

### 통과한 것 중 중요한 것

- **`- [ ] 제목 <!-- task:abc123 -->`** — §10 이 약속한 태스크 id 주석이 살아 돌아온다.
  노트 체크박스와 태스크 DB 를 잇는 장치라 이게 안 되면 §6.4 기능 전체가 무너진다.
- **`[[노트이름]]`** — 한글, 공백 포함 제목, 한 줄에 여러 개 모두 통과.
- **오탐 없음** — 코드블록 안의 `<!-- task:notreal -->` 은 태스크로 잡히지 않고,
  `arr[[0]]` 은 위키링크로 잡히지 않는다. 데이터 오염 경로가 막혀 있다.
- **중첩 리스트 안의 태스크** — 들여쓰기와 id 가 함께 유지된다.

### 서식변형 2건 (내용은 온전)

1. **태스크 여러 개** — 항목 사이에 빈 줄이 생긴다(loose list 로 재직렬화).
   id·체크 상태는 셋 다 정확히 보존된다.
2. **`*` 이스케이프** — `* 표시는` 이 `\* 표시는` 으로 저장된다.

둘 다 렌더 결과는 같지만, **저장할 때마다 파일이 사용자가 친 것과 달라진다**는 뜻이다.
A안을 채택한다면 이건 버그가 아니라 성질로 받아들여야 한다.

## A안을 채택할 때 따라오는 것

- **StarterKit v3 에는 Image 도 Table 도 없다.** 따로 등록해야 하고, 안 하면 이미지와 표가
  통째로 사라진다(조용한 데이터 손실). 이번에 `@tiptap/extension-image`,
  `@tiptap/extension-table` 을 넣고서야 통과했다.
- **tiptap-markdown 은 markdown-it 으로 HTML 을 만든 뒤 TipTap 의 HTML 파서에 넘긴다.**
  따라서 커스텀 인라인 문법은 markdown-it 규칙만으로 부족하고 **렌더러까지** 붙여 HTML 을
  내보내야 한다. 처음에 규칙만 넣었을 때 위키링크가 통째로 증발했다.
- 태스크 id 주석의 파싱은 `parse.updateDOM` 훅에서 HTML 주석을 data 속성으로 옮기는 방식으로
  했다. 중첩 리스트가 있으면 바깥 `li` 가 안쪽 주석을 삼키므로 **자기 소유의 체크박스·주석만**
  봐야 한다 — 이걸 안 하면 부모 항목에 자식의 id 가 붙는다.
- 직렬화 쪽은 `state.out` 을 후처리하는 방식이라 깔끔하지 않다. 실코드로 올릴 때 다시 봐야 한다.

## 이 프로토타입이 답하지 않은 것

A안의 **약점은 왕복이 아니라 동시편집**이다(§10.1). 이 프로토타입은 한 사람이 쓰고 저장하는
경로만 시험했다. LWW 통짜 덮어쓰기로 인한 유실 위험은 그대로 남아 있고, 그게 B안의 존재 이유다.
따라서 이 결과는 **"A안이 기술적으로 성립한다"** 는 것이지 **"A안이 옳다"** 는 것이 아니다.
최종 A/B 결정은 동시편집을 얼마나 중요하게 볼 것인가에 달렸다 — 그건 이 프로토타입이 아니라
제품 판단이다.

B안을 실제로 재보려면 `prosemirror-sync` 연동과 마크다운 Export 파생을 따로 시험해야 한다.

옮긴다.** TUI(`tui.ts`)만 버린다. 그 둘을 분리해 둔 이유가 이것이다.
