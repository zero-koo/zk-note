## 1. 프로젝트 개요

### 핵심 비전

기존 노트앱(Notion, Obsidian, Bear)의 장점을 취하되, 플러그인 설정 없이 처음부터 원하는 UI/UX와 기능을 갖춘 **마크다운 기반 개인 노트앱**. 핵심 차별점은 **노트 ↔ 태스크 ↔ 캘린더의 긴밀한 통합** 그리고 **독립 데스크탑 앱으로서의 네이티브 사용성**(브라우저 탭 의존 X, 향후 OS 수준 통합 — 예: 터미널 임베드 — 확장 여지).

### 포지셔닝

| 앱 | 장점 | 단점 |
|---|---|---|
| Notion | 기능 풍부, 협업 | 무거움, 순수 마크다운 아님 |
| Obsidian | 가볍고 마크다운 순수 | 플러그인 의존, UI 커스터마이즈 불가 |
| Bear | 깔끔한 UI | 기능 부족 |
| **ZK-Note** | 마크다운 호환 + 태스크/캘린더 통합 + 원하는 UX | — |

## 2. 타겟 사용자

- **1차**: 개발자/지식 작업자인 앱 제작자 본인 (Personal PKM + Task Management)
- **2차**: 마크다운에 익숙한 개인 사용자
- **MVP 단계**: 단일 사용자 계정 기반. 실시간 협업 없음.

## 3. 플랫폼

| 플랫폼 | 방식 | 우선순위 |
|---|---|---|
| **데스크탑 (macOS / Windows / Linux)** | **Tauri 셸 + 동일 React 코드** | **1순위 (MVP)** |
| 웹 브라우저 | TanStack Start 웹앱 (동일 코드 재사용) | 2순위 |
| 모바일 (iOS / Android) | PWA (동일 코드 재사용) | 3순위 |

### 플랫폼 결정 근거

- **데스크탑 1순위 이유**: 브라우저 탭에 의존하지 않는 독립 윈도우 / 시스템 단축키 / 메뉴바 / 트레이 등 네이티브 사용성 확보. 향후 **터미널 임베드, 로컬 파일 시스템 접근, 전역 단축키** 등 OS 통합 기능 확장을 위한 셸 확보.
- **Tauri 선택 이유**: Electron 대비 번들 사이즈 작음(~3MB → 실제 앱 < 20MB), 메모리 가벼움, Rust 기반 셸로 OS 통합 기능 확장 시 안전.
- **크로스플랫폼 코드 공유 원칙**: 데스크탑이 1순위지만, 동일한 React 코드가 웹과 PWA로도 빌드되도록 설계. 플랫폼 의존 코드는 추상화 레이어로 격리(아키텍처 문서 참고).
- **타 플랫폼에서의 편집**: 데스크탑에서 작성한 노트는 웹/모바일에서도 동일하게 조회·편집 가능해야 함 (Convex 클라우드 단일 소스이므로 자연스럽게 만족).

## 4. 기술 스택

| 영역 | 기술 |
|---|---|
| **데스크탑 셸** | **Tauri (Rust)** |
| 프론트 프레임워크 | TanStack Start (React) — 데스크탑 / 웹 / 모바일 공유 |
| 데이터베이스/백엔드 | Convex |
| 에디터 | TipTap |
| 인증 | Google OAuth (소셜 로그인 전용) |
| 모바일 배포 | PWA |

> **TanStack Start 선택 근거**: Start는 정식 **SPA 모드**(`spa: { enabled: true }` + 빌드 타임 prerender)를 지원해 Node 서버 없는 Tauri WebView에서 정상 동작한다(Tauri 2.0 + Start 공개 템플릿으로 검증됨). 동시에 웹 빌드에서는 **라우트별 SSR(selective SSR)**이 가능해, 향후 "읽기 전용 노트 공유" 같은 공개 페이지만 SSR로 제공하면서 앱 본체는 SPA로 유지할 수 있다 — 단일 코드베이스로 데스크탑(SPA)·웹(SPA+공유 SSR)을 모두 커버. 노트 공유 계획이 없다면 더 단순한 TanStack Router + Vite로도 대체 가능하며, Start → Router 이주 비용은 낮다.

## 5. 데이터 아키텍처

### 5.1 저장 구조

```
[Convex Cloud DB - 단일 소스]
  Notes 컬렉션
  Tasks 컬렉션 (독립 DB)
  Calendar 데이터
        ↓
  .md Export (필요 시)
```

- **단일 소스**: Convex DB가 모든 데이터의 원천
- **마크다운 호환성**: 에디터 내용이 표준 마크다운으로 저장되어, 복사/붙여넣기 시 GitHub, Obsidian, VS Code 등에서 완벽하게 렌더링됨
- **Export**: 노트를 `.md` 파일로 내보내기 가능 (단일 노트 / 폴더 전체)
- 로컬 `.md` 파일 실시간 동기화는 불필요

### 5.2 오프라인 전략 (온라인 우선)

Convex는 현재 **온라인 우선(online-first)** 모델이다. 영구 오프라인(앱 종료 후 재진입 시 데이터 보존)은 공식 sync 엔진이 아직 alpha 단계(`curvilinear`)이므로 MVP에서는 보장하지 않는다.

- **MVP**: 온라인 우선 + Convex 낙관적 업데이트로 짧은 네트워크 단절 내성. 온라인 복귀 시 자동 동기화.
- **데이터 유실 안전망(MVP 포함)**: 미동기화 에디터 버퍼를 로컬에 즉시 저장(데스크탑 Tauri FS/SQLite, 웹 IndexedDB)하여 오프라인 상태에서 앱을 종료해도 **방금 작성한 내용은 유실되지 않음**. 재진입 시 미동기 버퍼를 복원·재전송.
- **Phase 2**: Convex 공식 sync 엔진(Object Sync Engine / `curvilinear`)이 GA 되면 그것으로 영구 오프라인 전환(직접 구현하지 않음).
- **충돌 해결**: 기본은 Last-Write-Wins(`updatedAt` 비교). 단, 노트 본문은 LWW 통짜 덮어쓰기 시 데이터 유실 위험이 있어 별도 전략 검토(아키텍처 문서 §10 `prosemirror-sync` 결정 참고).

## 6. 핵심 기능 요구사항

### 6.1 에디터

| 항목 | 명세 |
|---|---|
| 방식 | WYSIWYG (Live Rendering) |
| 라이브러리 | TipTap |
| 마크다운 호환 | 입력/출력 모두 표준 마크다운 `.md` 파일로 저장 |
| 코드블록 | 신택스 하이라이트 필수 |
| 수식 | LaTeX/KaTeX 렌더링 필수 |
| 이미지/파일 | 첨부 및 인라인 렌더링 필수 |
| 다이어그램 | Mermaid 지원 (있으면 좋음) |
| 슬래시 명령어 | `/` 입력 시 블록 삽입 메뉴 (Daily Note, 태스크, 이미지, 코드블록 등) |

### 6.2 노트 구조 및 조직

| 항목 | 명세 |
|---|---|
| 폴더 계층 | 폴더/서브폴더 트리 (파일 시스템 기반) |
| 태그 | `#태그` 인라인 태깅, 태그별 필터링 |
| 양방향 링크 | `[[노트이름]]` 문법, 백링크 패널 |
| 전체 검색 | Full-text search (제목 + 본문) 필수 |
| 퀵 스위처 | `Cmd+K` 노트/태스크 빠른 이동 (있으면 좋음) |

### 6.3 Daily Note

| 항목 | 명세 |
|---|---|
| 자동 생성 | 앱 진입 시 오늘 날짜의 Daily Note 자동 생성 (`YYYY-MM-DD.md`) |
| 템플릿 | Daily Note 전용 템플릿 설정 가능 |
| 캘린더 연동 | 날짜 클릭 → 해당 날의 Daily Note로 이동 |
| 태스크 연동 | Daily Note 내 `- [ ] 할일` 작성 → 태스크 DB에 자동 생성 |

### 6.4 태스크 시스템 (핵심 차별점)

#### 구조

```
Task (독립 DB)
├── title: string
├── status: todo | in_progress | done
├── dueDate: date (optional)
├── detail: rich text (노션 토글처럼 펼쳐보기)
├── linkedNoteId: Note 참조 (optional)
└── linkedDate: Daily Note 날짜 (optional)
```

#### 동작 방식

| 시나리오 | 동작 |
|---|---|
| Daily Note에서 `- [ ] 할일` 입력 | 태스크 DB에 자동 생성 + 노트에 embedded 표시 |
| 노트에서 `/todo` 슬래시 명령어 | 태스크 선택 또는 신규 생성 후 노트에 삽입 |
| 태스크 제목 클릭 (노트 뷰) | 토글 확장 → 상세 내용 입력 가능 |
| 상세 내용 입력 | 태스크 DB의 `detail` 필드에 저장 |
| 태스크 뷰에서 열기 | 노트와 동일한 상세 내용 표시 |
| 체크박스 완료 (어디서든) | 태스크 DB `status` 업데이트 → 모든 뷰 동기화 |

#### 태스크 뷰

- **리스트 뷰**: 전체 태스크를 날짜/상태/태그별 필터
- **캘린더 뷰**: 마감일 기준으로 캘린더에 태스크 표시
- **Daily 뷰**: 특정 날짜의 태스크 + Daily Note 함께 표시

### 6.5 캘린더

| 항목 | 명세 |
|---|---|
| 월간 뷰 | 날짜별 태스크 수 / Daily Note 존재 여부 표시 |
| 날짜 클릭 | 해당 날의 Daily Note + 태스크 리스트 사이드패널 |
| 외부 연동 | Google Calendar 등 외부 연동은 향후 로드맵 |

| 항목 | 명세 | 단계 |

| 독립 윈도우 | 자체 메뉴바, 윈도우 컨트롤, 앱 아이콘 | MVP |

## 10. 미결 질문 (Open Questions)

1. **노트 공유**: 다른 사람에게 읽기 전용 링크로 노트를 공유하는 기능이 필요한가?
2. ~~**로컬 파일 동기화 메커니즘**~~ → 해결됨: Convex 단일 소스 + Export 방식으로 결정
3. **태스크 충돌**: 같은 태스크를 두 기기에서 동시 수정 시 Last-Write-Wins가 태스크 상세 내용에도 적용되는가?
4. **Daily Note 템플릿**: 사용자 정의 가능한가, 아니면 고정 포맷인가?
5. **팀/워크스페이스**: 향후 팀 기능을 추가할 계획이 있는가?
6. ~~**데스크탑 OAuth 콜백 방식**~~ → 해결됨 (2026-08-14, ADR-0004): **임시 루프백 서버**(`http://127.0.0.1:<port>`). 커스텀 URL 스킴은 채택하지 않는다 — Tauri 딥링크가 macOS 런타임 등록 불가라 서명 생략 상태의 현 개발 흐름으로는 검증조차 안 되고, Google도 데스크탑에 루프백을 권장한다. **WebView 안에서 Google 로그인 화면을 열면 안 된다**(`disallowed_useragent`) — 시스템 브라우저를 연다
7. **데스크탑 코드 서명/공증**: macOS 공증(Notarization) 및 Windows 코드 서명을 MVP 시점에 적용할 것인가? (개인 사용 단계에서는 생략 가능) — **부분 해결 (2026-08-15, ADR-0006)**: 자가 업데이트는 공증 없이 동작함이 실측됐다. **그러나 브라우저로 받는 첫 설치는 막힌다** — 지금은 터미널 설치로 우회한다. 이 우회가 불편해지는 시점이 공증 도입 시점이다
8. ~~**TanStack Start의 SSR**~~ → 해결됨: Start **SPA 모드**로 Tauri 빌드, 웹은 selective SSR. 뒤이어 제기됐던 **Convex WebSocket이 Tauri WebView(`tauri://localhost`) origin/CSP에서 유지되는가**도 2026-08-14 PoC로 해결됨 — 유지된다 (ADR-0001)
9. ~~**노트 본문 동시편집 유실**~~ → 해결됨 (2026-08-14, ADR-0003): `prosemirror-sync` 를 채택하지 **않는다**. 마크다운이 source of truth 로 유지된다. B 의 오프라인 편집 미지원 제약이 Phase 2 오프라인 목표와 충돌하는 것이 결정적이었다. **LWW 유실 위험은 남으므로** 저장 전 갱신 감지·충돌 알림으로 완화한다
10. **영구 오프라인 시점**: Convex 공식 sync 엔진(`curvilinear`) alpha 졸업 시점에 맞춰 Phase 2 도입할지, 그 전까지 미동기 버퍼 로컬 보존으로 버틸지
